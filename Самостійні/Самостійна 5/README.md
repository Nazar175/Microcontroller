# Самостійна робота №5

**Тема:** Програмування мікроконтролерів PIC. Компілятор HI-TECH та мова Асемблер

## Контрольні питання до лекції 5

### 1. Які особливості компілятора HI-TECH?

HI-TECH — це сімейство компіляторів, призначених для розробки програмного забезпечення мікроконтролерів. Зокрема, компілятор HI-TECH C використовується для програмування мікроконтролерів PIC мовою C.

Основні особливості компілятора HI-TECH:

- Підтримка мікроконтролерів сімейства PIC.
- Можливість програмування мовою C.
- Оптимізація програмного коду для зменшення обсягу пам'яті та підвищення швидкодії.
- Підтримка роботи з апаратними регістрами мікроконтролера.
- Можливість використання бібліотек та додаткових функцій.
- Створення машинного коду, який може бути записаний у пам'ять мікроконтролера.
- Інтеграція із середовищами розробки та засобами відлагодження.

Компілятор HI-TECH дозволяє розробникам створювати програми для мікроконтролерів без необхідності вручну записувати кожну машинну команду.

### 2. Формат запису команд мовою Асемблер.

Мова Асемблер — це низькорівнева мова програмування, команди якої відповідають машинним інструкціям процесора.

Кожен рядок програми мовою Асемблер має певну структуру та складається з таких основних частин:

1. **Мітка (Label)** — назва, яка позначає певну адресу програми та використовується для переходів.
2. **Мнемоніка (Mnemonic)** — назва команди, яку повинен виконати процесор.
3. **Операнди (Operands)** — дані або адреси, з якими виконується команда.
4. **Коментар (Comment)** — пояснення до команди, яке не впливає на виконання програми.

Загальний формат запису:

`Мітка    Мнемоніка    Операнди    ; Коментар`

Наприклад:

```asm
START   MOVLW   0x25    ; Завантаження числа 25 у регістр W
        MOVWF   PORTB   ; Запис значення з W у PORTB
        GOTO    START   ; Перехід на початок програми
```

Асемблер дозволяє безпосередньо керувати регістрами, пам'яттю та периферійними пристроями мікроконтролера.

### 3. Що таке псевдокоманди (директиви) та яку роль виконують?

Псевдокоманди, або директиви Асемблера, — це спеціальні інструкції для асемблера, які визначають правила обробки вихідного тексту програми.

На відміну від звичайних команд, директиви не виконуються безпосередньо мікроконтролером. Вони використовуються під час трансляції програми для організації пам'яті, визначення констант, створення змінних та налаштування параметрів компіляції.

Основні функції директив:
- визначення початкової адреси розміщення програми;
- оголошення констант і змінних;
- визначення областей пам'яті;
- організація структури програми;
- підключення додаткових файлів;
- налаштування параметрів асемблера.

Наприклад, директиви `ORG`, `EQU`, `END` та `INCLUDE` допомагають організувати вихідний код і правильно підготувати його до трансляції.

### 4. Яке призначення директиви ORG?

Директива `ORG` (Origin) використовується для встановлення початкової адреси розміщення наступних команд або даних у пам'яті мікроконтролера.

Вона дозволяє визначити, з якої адреси пам'яті повинна починатися певна частина програми.

Наприклад:

```asm
ORG 0x0000
GOTO START

ORG 0x0005
START
    MOVLW 0x10
    MOVWF PORTB

END
```

У цьому прикладі:
- `ORG 0x0000` — визначає початкову адресу програми.
- `GOTO START` — виконує перехід до основної частини програми.
- `ORG 0x0005` — встановлює адресу розміщення наступних команд.
- `END` — позначає завершення вихідного файлу.

Директива ORG особливо важлива для правильного розміщення векторів скидання та переривань.

### 5. Яке призначення директиви EQU?

Директива `EQU` (Equate) використовується для присвоєння символічного імені певному числовому значенню або адресі.

Вона дозволяє замінити числові значення зрозумілими назвами, що робить програму більш читабельною та спрощує її редагування.

Наприклад:

```asm
LED_PORT EQU PORTB
LED_PIN  EQU 0

START
    BSF LED_PORT, LED_PIN
```

У цьому прикладі:
- `LED_PORT` отримує значення `PORTB`;
- `LED_PIN` отримує значення `0`;
- команда `BSF` встановлює відповідний біт порту.

Основні переваги використання EQU:
- спрощення читання програмного коду;
- зменшення кількості повторюваних числових значень;
- полегшення внесення змін;
- підвищення зрозумілості програми.

Директива EQU не виділяє окрему комірку оперативної пам'яті, а лише визначає символічну відповідність значення.

### 6. Яка структура програми?

Програма для мікроконтролера PIC, написана мовою Асемблер, має певну структуру, яка забезпечує правильну організацію команд і налаштування пристрою.

Типова структура програми складається з таких частин:

1. **Заголовок програми** — містить назву, призначення та короткий опис програми.
2. **Підключення файлів** — підключення заголовків із визначеннями регістрів та інших необхідних параметрів.
3. **Визначення констант і змінних** — оголошення символічних імен за допомогою директив.
4. **Налаштування конфігурації** — встановлення параметрів роботи мікроконтролера.
5. **Вектор скидання** — адреса, з якої починається виконання програми після скидання.
6. **Основна частина програми** — містить команди, які виконують основні завдання пристрою.
7. **Підпрограми** — окремі блоки команд для виконання повторюваних операцій.
8. **Завершальна директива** — позначає кінець вихідного файлу.

Приклад простої структури програми:

```asm
; Підключення опису регістрів
INCLUDE <P16F84A.INC>

; Початкова адреса
ORG 0x0000
GOTO START

; Основна програма
START
    BSF STATUS, RP0
    CLRF TRISB
    BCF STATUS, RP0

MAIN
    BSF PORTB, 0
    GOTO MAIN

END
```

Така структура дозволяє логічно розділити програму на окремі частини та полегшує її розробку й перевірку.

### 7. За допомогою яких додаткових засобів вихідний текст компонується у вихідний модуль?

Для перетворення вихідного тексту програми у готовий програмний модуль використовується декілька спеціальних програмних засобів.

Основними з них є:

- **Препроцесор** — виконує попередню обробку вихідного коду, підключає заголовкові файли та обробляє макроси.
- **Компілятор** — перетворює програму з мови високого рівня у проміжний або об'єктний код.
- **Асемблер** — перетворює команди мови Асемблер у машинний код.
- **Компонувальник (Linker)** — об'єднує окремі об'єктні модулі та бібліотеки в одну програму, розподіляє пам'ять і вирішує адреси зовнішніх посилань.
- **Генератор HEX-файлів** — формує файл у форматі Intel HEX, який використовується для запису програми в пам'ять мікроконтролера.

Після виконання всіх етапів розробник отримує готовий файл прошивки, який можна завантажити в мікроконтролер за допомогою програматора.

### 8. Як відбувається відлагодження програм?

Відлагодження програм — це процес перевірки програмного коду з метою виявлення та виправлення помилок, які виникають під час його виконання.

Основна мета відлагодження — переконатися, що програма працює правильно та виконує всі поставлені завдання.

Процес відлагодження зазвичай складається з таких етапів:

1. **Перевірка синтаксису** — виявлення помилок у написанні команд та директив.
2. **Компіляція або асемблювання** — перетворення вихідного коду у машинний код.
3. **Перевірка помилок** — аналіз повідомлень компілятора або асемблера.
4. **Запуск програми в симуляторі** — перевірка роботи програми без використання реального мікроконтролера.
5. **Покрокове виконання** — перевірка виконання окремих команд та зміни значень регістрів.
6. **Перевірка змінних і регістрів** — аналіз стану пам'яті та внутрішніх блоків мікроконтролера.
7. **Тестування на реальному пристрої** — перевірка роботи програми з підключеними електронними компонентами.

Для відлагодження програм PIC можуть використовуватися такі засоби, як MPLAB IDE, MPLAB X IDE, симулятори та апаратні програматори й відлагоджувачі.

Завдяки цим засобам можна знаходити помилки, перевіряти правильність роботи окремих команд та вдосконалювати програму.
