# Самостійна робота №10

**Тема:** Система переривань мікроконтролерів сімейства PIC16.

## Відповіді на контрольні питання

### 1. Скільки джерел переривань мають мікроконтролери сімейства PIC16?

Кількість джерел переривань залежить від конкретної моделі мікроконтролера PIC16. Різні моделі можуть мати різну кількість периферійних модулів, які здатні генерувати переривання.

Наприклад, мікроконтролер PIC16F84 має три основні джерела переривань:
- Зовнішнє переривання через вивід RB0/INT.
- Переривання від переповнення таймера TMR0.
- Переривання під час зміни стану виводів RB4–RB7.

У більш складних моделях PIC16 можуть бути додаткові джерела переривань від модулів USART, АЦП, таймерів та інших периферійних пристроїв.

### 2. Який регістр керує перериваннями?

У мікроконтролері PIC16F84 основним регістром керування перериваннями є **INTCON** (Interrupt Control Register).

Він містить біти, які дозволяють вмикати або вимикати переривання, а також визначають, чи відбулася певна подія.

Основні біти регістра INTCON:
- **GIE** — загальний дозвіл на переривання.
- **EEIE** — дозвіл переривання від завершення запису в EEPROM.
- **T0IE** — дозвіл переривання від переповнення TMR0.
- **INTE** — дозвіл зовнішнього переривання RB0/INT.
- **RBIE** — дозвіл переривання при зміні стану RB4–RB7.
- **T0IF, INTF, RBIF** — прапорці, які вказують на виникнення відповідних подій.

Для роботи переривань потрібно правильно налаштувати відповідні біти дозволу та встановити загальний дозвіл GIE.

### 3. По відношенню до якого типу є переривання?

За способом виникнення переривання поділяють на два основні типи:

- **Апаратні переривання** — виникають унаслідок зовнішніх або внутрішніх апаратних подій. Наприклад, натискання кнопки, підключеної до RB0/INT, або переповнення таймера TMR0.
- **Програмні переривання** — викликаються спеціальними командами або програмними механізмами. У деяких мікроконтролерах для цього передбачені відповідні інструкції або механізми.

Також переривання можуть поділятися на зовнішні та внутрішні залежно від джерела сигналу.

У PIC16F84 апаратні переривання використовуються для швидкої реакції на події, не очікуючи, поки основна програма дійде до перевірки відповідного входу або таймера.

### 4. Для чого використовується стек?

Стек — це спеціальна область пам'яті, яка використовується для тимчасового збереження адрес повернення під час виклику підпрограм або обробки переривань.

Коли мікроконтролер виконує команду виклику підпрограми `CALL` або переходить до обробника переривання, адреса наступної команди зберігається у стеку.

Після завершення підпрограми команда `RETURN` або `RETFIE` використовує збережену адресу, щоб повернути виконання до попереднього місця програми.

У PIC16F84 апаратний стек має 8 рівнів. Він працює за принципом LIFO (Last In, First Out — останнім записаний, першим зчитаний).

Важливо, що стек PIC16F84 зберігає адреси повернення, але не призначений для автоматичного збереження всіх робочих регістрів мікроконтролера.

### 5. Як при переході до підпрограми обробки переривання зберегти значення регістрів STATUS?

Під час переходу до обробника переривання мікроконтролер автоматично зберігає адресу повернення у стеку, але значення робочих регістрів, зокрема STATUS і W, потрібно зберігати програмно.

Для цього перед виконанням основної частини обробника переривання значення регістрів копіюють у спеціально виділені комірки оперативної пам'яті. Перед поверненням із переривання збережені значення відновлюють.

Приклад для PIC16F84:

```asm
CBLOCK 0x0C
    W_TEMP
    STATUS_TEMP
ENDC

ORG 0x0004       ; Вектор переривання

INTERRUPT:
    MOVWF W_TEMP       ; Збереження W
    SWAPF STATUS, W    ; Копіювання STATUS у W
    MOVWF STATUS_TEMP  ; Збереження STATUS

    ; Тут розміщується обробка переривання

    SWAPF STATUS_TEMP, W
    MOVWF STATUS      ; Відновлення STATUS
    SWAPF W_TEMP, F
    SWAPF W_TEMP, W   ; Відновлення W

    RETFIE             ; Повернення з переривання
```

Команда `SWAPF` використовується для обміну місцями старшої та молодшої тетрад. Такий спосіб дозволяє зберегти та відновити значення STATUS, не змінюючи його прапорці під час відновлення.

Отже, правильне збереження регістрів дозволяє уникнути порушення роботи основної програми після завершення обробки переривання.

Також було опрацьовано призначення апаратних і програмних переривань, принцип роботи апаратного стека та збереження адрес повернення. Окрему увагу приділено збереженню робочих регістрів W і STATUS під час переходу до обробника переривання.

Отримані знання допомагають зрозуміти, як мікроконтролер реагує на важливі події та як організувати обробку переривань без порушення роботи основної програми.
